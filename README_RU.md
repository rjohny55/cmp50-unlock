## Выберите версию карты

| [CMP 50HX 10 ГБ](docs/10GB_RU.md) | [CMP 50HX 20 ГБ](docs/20GB_RU.md) |
| --- | --- |
| Исходная, наиболее полно проверенная конфигурация | Динамический WPR; четыре карты по 20480 МиБ проверены на ядре 6.8.0-137 |

> Обновление 20 ГБ от 26 августа 2026: исправлена причина Booter `0x8d` —
> фиксированная WPR-геометрия заменена на динамический per-BDF захват штатного
> FWSEC диапазона. Compute и RT-count прошли на четырёх картах. ReBAR требует
> холодной проверки, автоматический Gen2 пока экспериментальный.

Независимая копия с чистой историей, содержащая исследования и патчи для NVIDIA CMP 50HX. Оригинальные исследования, патчи, измерения и технические пояснения созданы **[xrip](https://github.com/xrip)** в проекте **[xrip/cmp50hx-unlock](https://github.com/xrip/cmp50hx-unlock)**.

В этом репозитории сохранены указание автора и ссылка на первоисточник. Материалы не выдаются за оригинальную работу владельца копии.

## Назначение

Набор патчей предназначен для открытых модулей ядра NVIDIA версии `610.43.03` и проверенных PCI-идентификаторов CMP 50HX:

| Поле | Значение |
| --- | --- |
| GPU | NVIDIA CMP 50HX / TU102 |
| PCI vendor/device | `10de:1e09` |
| Подсистема NVIDIA | `10de:1554` |
| Подсистема MSI | `1462:371f` |
| Исходники драйвера | NVIDIA open-gpu-kernel-modules `610.43.03` |

Проект содержит четыре патча, применяемых по стадиям:

1. `01-cmp50-stockflow.patch` — ограниченный конкретной платой путь GSP/RM stockflow и изменение скорости выдачи инструкций SM.
2. `02-cmp50-rt-core-count.patch` — отображение количества RT-ядер на стороне host/RM.
3. `03-cmp50-rebar.patch` — настройка ReBAR для CMP50.
4. `04-cmp50-pcie-gen2.patch` — перевод PCIe endpoint и upstream bridge в режим Gen2 с повторным согласованием линии.

Сборщик поддерживает `CMP50_PATCH_STAGE=stockflow|rt|rebar|gen2`; безопасное
значение по умолчанию — `rt`. Автоустановщик: `sudo ./install.sh --help`.

Подробное объяснение регистров, уровней доказательности, результатов измерений и ограничений сохранено в [docs/UPSTREAM_README.md](docs/UPSTREAM_README.md). Дополнительные исследовательские материалы находятся в [docs/CMP50HX.md](docs/CMP50HX.md).

## Важные ограничения

- Это экспериментальное низкоуровневое исследование GPU и модулей ядра.
- Патчи ограничены точными PCI ID. Не удаляйте эти проверки.
- Отображение 56 RT-ядер меняет значение host API, но **не** включает физическое исполнение RT-инструкций.
- Работа ReBAR и PCIe зависит от прошивки материнской платы, ресурсов PCI bridge, версии ядра и конкретной платы.
- Ошибочный модуль ядра или изменение, связанное с firmware, может нарушить загрузку системы, дестабилизировать GPU или потребовать восстановления через другое ядро.
- До тестирования сохраните рабочее ядро, initramfs, пакет драйвера и обеспечьте удалённый либо локальный аварийный доступ.

## Требования для сборки

Скрипту сборки требуются Linux, заголовочные файлы текущего ядра, компилятор C, GNU make, curl, patch, tar, `modinfo` и основные системные утилиты. Используется зафиксированный исходный архив:

```text
https://github.com/NVIDIA/open-gpu-kernel-modules/archive/refs/tags/610.43.03.tar.gz
SHA-256: 9df87d753cd9c05aa0eedc462af9b35debb549a657136e863282f94c96ee2640
```

Перед выполнением внимательно изучите `build.sh` и каждый патч. Импортированный snapshot нужно рассматривать как исследовательский материал: сначала убедитесь, что в checkout присутствуют все пути и вспомогательные исходники, на которые ссылается скрипт.

Предусмотренный интерфейс скрипта:

```bash
bash ./build.sh
bash ./build.sh --source-dir /path/to/open-gpu-kernel-modules
bash ./build.sh --source-tarball /path/to/610.43.03.tar.gz
```

Скрипт предназначен только для создания артефактов. Он не устанавливает и не загружает модули, не выгружает текущий драйвер и не сбрасывает GPU.

## Безопасный порядок проверки

1. Проверьте точные PCI ID устройства и подсистемы командой `lspci -nn`.
2. Проверьте версию запущенного ядра и установите строго соответствующие заголовочные файлы.
3. Изучите четыре патча в порядке их применения.
4. Выполните пробное применение патчей к чистому и проверенному по хешу дереву NVIDIA.
5. Соберите артефакты без установки.
6. Проверьте версию модулей, vermagic, строки и контрольные суммы.
7. Подготовьте откат и аварийный доступ.
8. Только после этого тестируйте на некритичном сервере с целевой картой.
