# CMP 50HX 10 GB

[Main README](../README.md) · [Русский](10GB_RU.md) · [20 GB variant](20GB.md)

## Status

This is the original and most thoroughly validated project configuration. The
target is PCI device `10de:1e09`, subsystem `10de:1554` or `1462:371f`, with
NVIDIA Open `610.43.03`.

| Capability | 10 GB status |
| --- | --- |
| GSP/RM stockflow | Validated by the original project |
| Full SM issue rate | Validated |
| CUDA / Tensor | 3584 / 448, validated |
| RT count | RM reports 56; real RT instructions remain locked |
| ReBAR | 16 GiB BAR1 validated by the original project after a cold boot |
| PCIe Gen2 | Validated by the original project on its x4 host |
| Idle governor | Optional; validate manually before enabling |

The current `01-cmp50-stockflow.patch` no longer assumes a fixed WPR address
for a particular VRAM size. It captures the range created by stock FWSEC,
requires a `0xe00` span, and uses that per-BDF value afterward. This preserves
the 10 GB path while supporting 20 GB boards with different WPR geometry.

## Recommended staged installation

```bash
git clone https://github.com/rjohny55/cmp50-unlock.git
cd cmp50-unlock
sudo ./install.sh --stage stockflow --install-userland

CMP50_PATCH_STAGE=rt bash ./build.sh
CMP50_PATCH_STAGE=rebar bash ./build.sh
CMP50_PATCH_STAGE=gen2 bash ./build.sh
```

Pass `--initramfs` to the installer when staging a validated module in the
initramfs. ReBAR requires a cold boot. Do not advance to the next stage until
the current one passes `sudo ./verify-live.sh`.

## Important RT limitation

Patch `02` changes only the RT-core count returned by RM. On CMP 50HX, the
ray-query opcode still ends in `INVALID_OPCODE`; the physical RT path is
considered fuse/floorsweep-disabled. Do not present the value 56 as working
ray tracing.
